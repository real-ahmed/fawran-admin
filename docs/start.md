# Fawran React Admin Dashboard - AI Agent Build Guide

Hello AI Agent! Your task is to build a modern, highly responsive, and premium Admin Dashboard for the "Fawran" application. You will be acting as an expert Frontend Developer.

## Tech Stack & Core Requirements
- **Framework:** React (Next.js App Router or Vite - depending on user preference, default to Vite for SPA).
- **Styling:** Tailwind CSS.
- **UI Components:** shadcn/ui (Radix UI primitives).
- **Icons:** Lucide React.
- **State Management:** React Query (for API data fetching and caching) & Zustand (for lightweight global state if needed).
- **Form Handling:** React Hook Form + Zod validation.

## Design Aesthetic & Branding
- **Primary Color:** `#606C38` (Dark Olive Green) - Use for primary buttons, active links, and key highlights.
- **Secondary/Background Color:** `#CCD5AE` (Light Olive Green) - Use for soft backgrounds, sidebars, wrapper components, and accents.
- **Surface:** White (`#FFFFFF`) for cards and inner containers to ensure high contrast and readability.
- **Text:** Dark slate/gray for readability (`#18181b` or `#52525b`).
- **Feel:** Premium, dynamic, modern. Incorporate subtle hover micro-animations, glassmorphism where appropriate, and clean padding/margins.

## Authentication Architecture
- The backend uses JWT tokens.
- On successful login (`/api/v1/admin/login`), store the token securely (e.g., in a secure HTTP-only cookie or memory/localStorage depending on setup).
- Every API request must include the header: `Authorization: Bearer <token>`.
- Implement Axios or fetch interceptors to automatically handle 401 Unauthorized responses and refresh tokens (`/api/v1/admin/refresh`).

## Complete API Endpoint Reference

All endpoints are prefixed with the base URL: `YOUR_BASE_URL/api/v1`

### 0. Public App Configuration
- **`GET /public/app-config`** - Retrieve essential public UI/Branding settings (e.g., `app_name`, `app_icon`, `favicon`). Hit this on launch to dynamically style the app before login!

### 1. Authentication & Profile
- **`POST /admin/login`** - Authenticate admin and receive JWT.
- **`POST /admin/logout`** - Invalidate current token.
- **`GET /admin/me`** - Get current authenticated admin details.
- **`POST /admin/refresh`** - Refresh the JWT token.
- **`POST /admin/forgot-password`** - Request a password reset OTP.
- **`POST /admin/verify-reset-otp`** - Verify the 6-digit OTP.
- **`POST /admin/reset-password`** - Set the new password.
- **`PUT /admin/profile/settings`** - Update admin profile settings.

## Role-Based Access Control (RBAC) & Permissions Sync

To ensure that admins only see the screens and buttons they have access to, implement the following RBAC strategy:

1. **Fetch & Store Permissions:**
   - On successful login (or during app initialization if a valid JWT exists), the call to `GET /admin/me` will return the user's assigned `role` and an array of `permissions`.
   - Store this `permissions` array globally in your state manager (e.g., inside a Zustand `useAuthStore`).

2. **Protecting Routes (Screen Level):**
   - Create a reusable wrapper component (e.g., `<ProtectedRoute requiredPermission="view_vendors">`).
   - Wrap your React Router or Next.js layout routes with this component. If the user’s stored permissions array does *not* contain the required permission, automatically redirect them to a `403 Forbidden` or `Not Authorized` page, or back to the Dashboard.

3. **Filtering the Sidebar (Navigation Level):**
   - Define your sidebar navigation items as an array of objects, where each item includes a `permission` key.
   - Example: `{ title: "Vendors", path: "/vendors", permission: "view_vendors" }`.
   - Map over this array and *only* render the `MenuItem` if `userPermissions.includes(item.permission)`. This ensures unauthorized users never even see the link to screens they can't access.

4. **Protecting UI Actions (Button Level):**
   - Create a helper component `<Can permission="delete_vendors">`.
   - Wrap sensitive UI elements (like "Delete", "Approve", or "Create" buttons) inside this component. If the permission is missing, the component should return `null` (hiding the button) or render a disabled state.
